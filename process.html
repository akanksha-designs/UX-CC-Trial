Designer Workflow · Vibe-Coding · Design System

How I work with Claude
from Figma to production.

A real, end-to-end workflow — no hand-off, no in-between. Design changes go from Figma into code, reviewed on localhost, and deployed to Vercel in a single session.

01 Access

Connect with GitHub

Before anything else, you need access to the GitHub repository where the codebase lives. GitHub is the source of truth for all code — it tracks every change, who made it, and why.

What to do

  1. Create a GitHub account at github.com if you don't have one
  2. Ask the repo owner to add you as a collaborator (Settings → Collaborators)
  3. Generate a Personal Access Token — GitHub no longer accepts passwords
    Profile → Settings → Developer Settings → Tokens (classic) → repo scope
  4. Save the token somewhere safe — you'll use it as your password in the terminal
02 Setup

Connect Claude to Figma via MCP

MCP (Model Context Protocol) lets Claude read your Figma files directly — components, tokens, styles, and layouts — so it can translate design intent into code without you copy-pasting values.

Steps to connect

  1. Open Claude Desktop → Settings → Developer → Edit Config
  2. Add the Figma MCP server to your config: 
    {
  "mcpServers": {
    "figma": {
      "command": "npx",
      "args": ["-y", "figma-developer-mcp", "--figma-api-key=YOUR_KEY"]
    }
  }
}
  3. Get your Figma API key → Figma → Profile → Settings → Personal access tokens
  4. Restart Claude Desktop — you'll see a Figma plug icon in the toolbar when it's connected
→ Once connected, you can share a Figma frame URL with Claude and it reads the design directly — colours, spacing, component names, and variables.
03 Local Setup

Clone the repo & set up locally

To make changes, you need a local copy of the code on your machine. This is called "cloning." Once cloned, Claude Code can read and edit the files directly.

Terminal commands — run these once

# 1. Navigate to where you want the project
cd /Users/yourname/Explorations

# 2. Clone the repo (copy from GitHub to your machine)
git clone https://github.com/your-org/your-repo.git

# 3. Move into the project folder
cd your-repo

# 4. Confirm git knows who you are
git config user.name "Your Name"
git config user.email "you@example.com"

# 5. Start the local dev server
python3 -m http.server 3001

Connect Claude Code to the project

  1. Open Claude Code (desktop app or claude in terminal)
  2. Open the project folder — Claude now has full read/write access to all files
  3. Claude can run terminal commands, edit files, and preview changes — all from the chat
04 Branching

Branch out for every change

A branch is an isolated copy of the code where you can make changes safely — without affecting the live site or anyone else's work. Think of it like working on a duplicate Figma file before merging changes into the main one.

→ Why it matters: If something breaks on your branch, main (production) is untouched. Every branch also gets its own Vercel preview URL — so stakeholders can review before anything goes live.

Create a branch for your change

# Always start from the latest main
git checkout main
git pull origin main

# Create and switch to a new branch
git checkout -b design/your-change-name

# Example:
git checkout -b design/update-hero-colours

Branch naming convention

  • design/hero-typography — visual/layout change
  • design/colour-tokens — design system update
  • fix/nav-mobile — bug fix
05 Vibe-Coding

Feed Figma into Claude & vibe-code the changes

This is the core of the workflow. You share your Figma design — colour tokens, component specs, or a full frame — with Claude, describe what you want changed, and Claude edits the actual code files.

What to share with Claude

  • Figma frame URL — Claude reads layout, spacing, and component structure via MCP
  • Colour tokens — paste the variable list from Figma or share the Variables panel
  • Design system components — share the component URL and Claude maps it to code
  • Screenshots — for quick visual changes Claude can infer from the image

Example prompts

"Update the hero heading colour to match the Primary/500
token from this Figma frame: [url]"

"The card component in Figma uses 16px padding,
border-radius 12px, and a 1px #2a2a30 border.
Apply that to .card in style.css"

"Here are the new colour tokens from Figma — replace
all the hardcoded hex values in style.css with these
CSS variables"
→ Claude edits style.css, index.html, or any file directly. The local server reloads automatically — you see the change instantly at localhost:3001.
06 Review

Review on localhost

Before anything is committed, review the change at http://localhost:3001. This is your private sandbox — nothing is public yet.

What to check

  • Does it match the Figma design?
  • Does it look right on mobile? (resize the browser to ~375px)
  • Are there any visual regressions elsewhere on the page?
  • Does hover, focus, and scroll behaviour still work?

If something's off — tell Claude. Describe what's wrong or share a screenshot. Claude iterates until it matches.

07 Ship

Commit, push & open a PR

Once you're happy with the change locally, you save it to GitHub and open a Pull Request — a formal proposal to merge your branch into main.

Terminal commands

# Stage all changed files
git add .

# Commit with a clear message
git commit -m "Update hero colours to match Figma Primary/500 token"

# Push your branch to GitHub
git push -u origin design/update-hero-colours

Open the Pull Request

  1. Go to the repo on GitHub — you'll see a yellow banner: "Compare & pull request"
  2. Click it, fill in the PR template (Figma link + before/after screenshots)
  3. Submit — Vercel instantly posts a preview URL as a comment on the PR
08 Review & Deploy

Get the PR reviewed & merge

A reviewer (or you, for solo projects) checks the Vercel preview URL, leaves comments if needed, and approves. Once approved, merge into main — Vercel deploys automatically.

Review checklist

  • Open the Vercel preview URL from the PR comments
  • Compare against the Figma frame linked in the PR
  • Check mobile view on the preview URL
  • Approve → Merge → Delete branch
→ Merging to main triggers a Vercel production deploy. Usually live within 30–60 seconds.
09 Verify

Verify on the deployed version

Always check the live URL after deploy — not just the preview. Production can sometimes behave differently (caching, CDN, environment differences).

Final checks

  • Open the live URL — hard refresh with Cmd+Shift+R to clear cache
  • Check on an actual mobile device, not just a resized browser
  • Confirm the Figma design intent is fully realised
  • Done — loop back to Figma for the next change
→ The full loop — Figma to production — typically takes under 30 minutes for a focused visual change.
